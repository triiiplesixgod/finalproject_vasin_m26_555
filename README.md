# ValutaTrade Hub

Учебный консольный проект - симулятор торговли валютами (фиатными и
криптовалютами). Пользователь регистрируется, пополняет виртуальный
портфель, покупает и продаёт валюту по курсам, которые обновляются
отдельным сервисом из реальных внешних API.

## Установка

```powershell
git clone <ссылка-на-репозиторий>
cd finalproject_vasin_m26_555
uv sync
```

Команда `uv sync` создаст виртуальное окружение и установит все
зависимости, перечисленные в `pyproject.toml` (`requests`,
`python-dotenv`, `prettytable`), а также dev-зависимости (`ruff`).

## Настройка (.env)

Для работы Parser Service с фиатными валютами нужен бесплатный API-ключ
[ExchangeRate-API](https://www.exchangerate-api.com/):

1. Зарегистрируйтесь на сайте и получите ключ.
2. Создайте в корне проекта файл `.env` (он уже добавлен в `.gitignore`
   и не попадёт в git):

```powershell
Set-Content -Path .env -Value "EXCHANGERATE_API_KEY=ваш_ключ_здесь"
```

Ключ подхватывается автоматически через `python-dotenv` при создании
`ParserConfig`. CoinGecko используется без ключа (публичный эндпоинт).

**Важно:** ключ никогда не хранится в коде - только в `.env`

### Просмотр портфеля

```
> show-portfolio

```

Выводит список валют в портфеле пользователя с пересчётом стоимости в
указанную базовую валюту (по умолчанию USD) и итоговую сумму.

### Покупка и продажа валюты

```
> buy --currency BTC --amount 0.01
> sell --currency BTC --amount 0.005
```

Покупка/продажа выполняется за USD по актуальному курсу из кэша
Parser Service. При нехватке средств выводится понятное сообщение об
ошибке, кошелёк в нужной валюте создаётся автоматически при первой
покупке.

### Курс одной пары валют

```
> get-rate --from BTC --to USD
Курс BTC->USD: 80014.00 (обновлено: 2026-10-26 14:23:47)
Обратный курс USD->BTC: 0.00001250
```

### Обновление курсов вручную

```
> update-rates
Курсы обновлены: 6 пар(ы) в кэше, 6 новых записей в истории.
Успешные источники: CoinGecko, ExchangeRate-API.

> update-rates --source coingecko
> update-rates --source exchangerate
```

Опция `--source` позволяет обновить курсы только из одного источника
(`coingecko` - криптовалюты, `exchangerate` - фиатные валюты). Если
один из источников недоступен, обновление остальных не прерывается -
в сообщении будет указано, какой источник не ответил.

## Parser Service

Курсы валют **не хранятся в коде** и не являются статичной заглушкой -
они приходят из реальных внешних API:

- [CoinGecko](https://api.coingecko.com) - криптовалюты (BTC, ETH, SOL
  и др.), без API-ключа;
- [ExchangeRate-API](https://www.exchangerate-api.com) - фиатные
  валюты (EUR, GBP, RUB и др.), требует ключ в `.env`.

Все курсы приводятся к единой базовой валюте - **USD**.

### Файлы данных Parser Service

- **`data/rates.json`** - снимок (кэш) текущих курсов. Формат:
  ```json
  {
    "pairs": {
      "BTC_USD": {"rate": 80014.0, "updated_at": "2026-10-26T14:23:47Z", "source": "CoinGecko"},
      "EUR_USD": {"rate": 0.8922, "updated_at": "2026-10-26T14:23:47Z", "source": "ExchangeRate-API"}
    },
    "last_refresh": "2026-10-26T14:23:47Z"
  }
  ```
  Для каждой пары хранится только последнее значение - при обновлении
  побеждает более свежая запись (`updated_at`).

- **`data/exchange_rates.json`** - полная история всех измерений
  (журнал). Каждая запись содержит уникальный `id`
  (`<FROM>_<TO>_<ISO-UTC timestamp>`), `rate`, `timestamp`, `source` и
  метаданные запроса (`raw_id`, `request_ms`, `status_code`, `etag`).
  Запись в журнал происходит только атомарно (через временный файл и
  `rename`) и только после успешного и провалидированного ответа API.

### TTL (время жизни курса)

Время жизни курса в кэше задаётся в `SettingsLoader.rates_ttl_seconds`
(по умолчанию **300 секунд**). Это значение используется для того,
чтобы понимать, насколько курс "свежий" - при отображении курса в
`get-rate`/`show-rates`, если курс в кэше старше TTL, приложение не
блокирует операцию (покупка/продажа по-прежнему возможна), но это
сигнал, что стоит выполнить `update-rates` для получения актуальных
данных.

### Как включить обновление курсов

**Вариант 1 - вручную, из CLI:**

```
> update-rates
```

**Вариант 2 - автоматически, фоновым планировщиком:**

```powershell
uv run python -m valutatrade_hub.parser_service.scheduler
```

Планировщик в бесконечном цикле вызывает обновление курсов каждые
`rates_ttl_seconds` секунд (по умолчанию 300) и логирует каждый шаг в
`logs/parser.log`. Остановка - `Ctrl+C`.

Если ни один из вариантов не запускался, `rates.json` будет пустым, и
операции, требующие курс (`buy`, `sell`, `get-rate`, `show-rates`),
сообщат об этом с подсказкой выполнить `update-rates`.

## Логирование

Проект ведёт два независимых лог-файла:

- **`logs/actions.log`** - действия пользователя (`REGISTER`, `LOGIN`,
  `BUY`, `SELL`) через декоратор `@log_action`.
- **`logs/parser.log`** - работа Parser Service (запросы к API,
  успехи/ошибки источников, итоги обновления).

Оба лога используют ротацию (`RotatingFileHandler`, до 1 МБ на файл, 3
резервные копии) и не дублируют сообщения друг в друга.
